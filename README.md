# Fitbit Activity Processing Workflow

This repository contains the notebooks released in the All of Us Researcher Workbench workspace **ML4H Benchmark for Wearable Data Processing**. They extract, quality-control, process, and summarize longitudinal Fitbit data, and prepare a participant-day table for downstream ML modeling. The notebooks are intended to be run sequentially, with intermediate outputs from each step used as inputs to the next.

The notebooks target CDR v8 (`C2024Q3R9`). Because of the scale of the underlying Fitbit data, the extraction and ingestion steps (001 and 002) process participants in chunks of about 1,000 individuals rather than loading the full cohort at once. Chunks 1–37 cover participants with EHR data and chunks 38–60 cover participants without EHR data. Completed chunks are skipped on rerun.

## Repository structure

```
.
├── 001_v8_data_grab_release.ipynb
├── 002_v8_qc_ingestion_release.ipynb
├── 003_v8_data_prepare_for_ML_release.ipynb
├── 004_v8_trends_calculation_release.ipynb
├── 005_v8_trends_figures_release.ipynb
└── filepaths_values.csv
```

### `001_v8_data_grab_release.ipynb`

Extracts Fitbit activity, heart rate, and sleep data from the source SQL tables and saves them as TSV files for downstream processing. Participants are divided into chunks, and the data for each chunk are queried and saved separately. This notebook also writes the shared `test_flag.txt` file read by notebooks 002–005.

**Output:** TSV files containing the extracted Fitbit data for each participant chunk, along with the participant IDs assigned to each chunk.

### `002_v8_qc_ingestion_release.ipynb`

Performs quality control and preprocessing of the extracted Fitbit data, following the chunking defined in 001. Participant-level QC runs in parallel on a Dataproc cluster. Processed data are saved as participant-level HDF5 files.

**Input:** TSV files generated by `001_v8_data_grab_release.ipynb`
**Output:** HDF5 files for individual participants.

### `003_v8_data_prepare_for_ML_release.ipynb`

Builds a participant-day table for ML modeling. It summarizes daily heart rate, steps, sleep levels, and activity measures from the HDF5 files, adds EHR-derived BMI and sex at birth, and identifies EHR history and follow-up dates for each participant.

**Input:** HDF5 files generated by `002_v8_qc_ingestion_release.ipynb`
**Output:** Participant-level JSON files and a combined participant-day table (Parquet) for model training.

### `004_v8_trends_calculation_release.ipynb`

Calculates longitudinal activity trends from the processed participant-level data across all available participants. Summary measures and temporal activity statistics over each participant's follow-up are saved to participant-level JSON files.

**Input:** HDF5 files generated by `002_v8_qc_ingestion_release.ipynb`
**Output:** JSON files containing participant-level activity trend calculations.

### `005_v8_trends_figures_release.ipynb`

Generates population-level and stratified figures describing temporal patterns in activity using the participant-level trend calculations.

**Input:** JSON files generated by `004_v8_trends_calculation_release.ipynb`
**Output:** Figures summarizing temporal activity trends.

## Test mode

Set `TEST = True` in notebook 001 to run the full pipeline on a small subset of participants. The setting is written to `test_flag.txt` in the workspace bucket and picked up automatically by notebooks 002–005.

## File paths

The notebooks reference several input and output directories. Example paths are provided in:

```
filepaths_values.csv
```

Users should replace these example paths with locations appropriate for their environment. The file can also be renamed if preferred, provided the corresponding filename is updated in the notebooks.

For example:

```python
file_paths_values = pd.read_csv("filepaths_values.csv")

file_paths_values = file_paths_values[
    file_paths_values["notebook"] == "trends_figures"
][["notebook", "key_", "value_"]]

paths_dict = file_paths_values.set_index("key_")["value_"].to_dict()
```

The `notebook` column identifies the notebook using a given path, `key_` provides the variable name used within the notebook, and `value_` contains the corresponding filesystem path.

## Recommended execution order

Run the notebooks in numerical order:

```
001 → 002 → 003 → 004 → 005
```

Notebooks 003 and 004 both read the HDF5 output of 002 and are independent of each other. Each notebook contains documentation of its compute requirements and processing steps.
